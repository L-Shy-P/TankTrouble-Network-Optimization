# 技术说明（中文）— 原理、实测结论、踩过的坑

> 这份文档记录的是**实测出来**的结论，不是推测。每一条后面都尽量附上证据或复现方式，
> 免得以后（包括我自己）再走一遍回头路。

---

## 0. 一句话原理

TankTrouble 是「**浏览器里跑完整物理模拟 + 服务端做权威校验**」的架构，局内走 WebSocket（TCP）。
所以丢包**不会**变成"丢了一条按键事件"，而是变成"**整体僵住一小段 → 积压的帧一次性补发**"
（TCP 队头阻塞 + 重传）。客户端改不了网络，但可以把"僵住 → 瞬移"这段体验修掉：

> **渲染期插值**（只改画的那一瞬间）+ **本地权威**（自己坦克不接受服务端回拉）+ **静默期外推**（别让实体冻住）。

**没有服务器、没有网络配置、不是加速器**：服务端看到的数据一个字节都没变。

## 1. 改「精灵状态」是死的 ❌，改「绘制瞬间」才是对的 ✅

**踩过的坑**：一开始直接在精灵的 `x/y` setter 里把坐标换成平滑值。游戏会把精灵坐标**读回模型**，
于是两边互相拽 —— 表现就是"**不开几乎不卡，开了狂抖**"。

**实测证据**（同一局、同一段操作）：

| 方案 | 写入次数 | `frameJumps` |
|---|---|---|
| 优化关（对照） | 199552 | **0** |
| 改状态式平滑 | 47515 | **1847** |

另一条佐证：`ignored: 895` 但 `divergence: 0` —— 明明"忽略了服务端修正"，与真值的偏差却是 0，
说明游戏在把精灵坐标读回去当模型。

**正确做法（当前实现）**：精灵坐标**一个字节都不改**，只在 `_renderWebGL` / `_renderCanvas`
被调用的那一瞬间把坐标临时换成平滑值，`finally` 里立刻还原。
游戏逻辑、相机、服务端校验全程看到真值 —— 这就是渲染期插值。

代价：它只影响**画面**，不影响判定（你看到的位置比真实位置"晚"一点点）。

## 2. 游戏协议（已解出，供以后参考）

* 局内连接：`wss://{region}-mp{n}.tanktrouble.com:443`，**同一连接上混合文本 JSON 与二进制帧**。
* 区域：`asia-central1`、`eu-west1`、`us-east1`(mp2)、`us-east2`、`us-south1`、`us-west1`、`australia-east1`；
  游戏每 ~30s 探测全部 7 个，选 RTT 最低的。脚本的 `probeRegions()` 复刻了这个过程。
* 二进制帧格式（IEEE754 大端）：
  * 子弹/实体：`[len][id][len][ownerId][vx][vy][flag][x][y]`
  * 坦克：`[len][playerId][flag][rot][x][y]`
  * 武器：`[len][weaponId][playerId][len][JSON{_numBullets,_triggerPulled,_bulletsFired,_timeAlive}]`
* **出站**（`02` 前缀）：`[playerId][flag][rot][x][y]` —— 客户端**每帧上报自己的位置**，
  这也是"服务端会回声/修正你的位置"的来源。
* 文本帧都带 `_typeId`（3/4/5/8/9/15/16/25/26/28/29/31/39/44/51/54/56/57…）。
* **`_typeId:15` → `_typeId:28`** 是延迟探测（客户端发 15，服务端回 28），脚本用它量真 RTT。
* ⚠️ **协议里没有时间戳/序号**，所以"按服务端时间戳过滤旧状态"这条路**走不通**；
  只能靠**位移大小**区分"本地增量"和"服务端修正"。

## 3. 网络层：能做的只有这些 ✅

| 手段 | 做法 | 效果 |
|---|---|---|
| 渲染期平滑 | 单帧位移上限按 **p25** 估算（不是中位数、更不是 p90 —— 抖动会把它们抬高，于是抖动被当成"正常速度"放行），并保证在 600ms 内收敛，2400ms 兜底硬对齐 | 把"瞬移"变成"滑行" |
| 本地权威 | 自己的坦克：写入 ≤ `中位单帧位移 × 3` 当作本地物理增量采纳；超过则当作服务端回声/修正**不采纳**（计入"忽略修正"） | 断线期间还能开；断线结束后**位置不会被拉回**；平时不会被迟到的旧位置往回弹 |
| 静默期外推 | 静默 >150ms 且模型不动 → 按最后速度外推，最多 30 帧（≈500ms），到期原地停住 | 实体不会冻住，也绝不往回跳 |
| 回合事件对齐 | 复活/重开/换图由 `TANK_CREATED`/`ROUND_STARTED` 等事件直接对齐 | 不会"飘"到出生点 |

**它不做什么**：不能让网络不卡（TCP 重传该发生还是发生），不改协议、不重写包、不注入包。
面板上的数字是**诊断**，不是优化本身。

## 4. 指标：怎么量才算"准"

* **帧间隔 ≠ 延迟**。游戏空闲时帧就停了，间隔能到几千毫秒。
  所以"延迟"只认 ping 的 RTT；帧到达节奏只用来算**抖动**和**卡顿**。
* **区分"真卡顿"和"空闲"**：两者都是"很久没帧"，但
  * 真卡顿（队头阻塞）→ 之后有**补发洪流**（`burstFrames ≥ 3`）
  * 大厅/局间空闲 → 之后只有正常节奏的一帧（`burstFrames ≈ 1~2`）

  判据：`停顿 ≥ 正常节奏 × 3` **且** `burstFrames ≥ 3`。
  不做这个区分的话，"最大延迟"会永远停在几千毫秒、稳定度被拉到 0（**用户实测过**）。
* **稳定度**优先级：帧节奏（对局中最准）→ RTT 抖动（实时兜底）→ 沿用上次（60s 内，标 `≈`）→ 才算没数据。
  帧样本不足时窗口从 20s 放宽到 60s；**绝不因为"大厅没帧"就空着**。
* **延迟来源**有三种，面板"状态"行会说清用的是哪个：
  `probe`（自建 2s 探测） / `game`（配对游戏自己的 `_typeId:15→28`） / `none`。

## 5. HUD：踩过的坑（都写成了回归测试）

| 坑 | 症状 | 规矩 |
|---|---|---|
| 自己的探测连接被当成"游戏连接" | 悬浮球**一直灰、什么数据都不显示**（探测 2 秒才一帧 → 帧样本永远不够） | 自己开的连接必须打 `probe` 标记并从"主连接"里排除；游戏自己开的单帧短命探测连接也要排除 |
| 展开动画自动"躲"出屏 | 球在左下角，面板却往左上角展开（不是从球里长出来） | **面板左上角始终与悬浮球一一对应**，动画期间不夹取；越界就让它越界，**展开结束再用 240ms 回弹推回来** |
| 回弹/惯性被面板刷新掐停 | 球刚甩出去就被下一次 `refreshHud`（每 250ms 调 `clampHud`）停住 | 没越界时 `clampHud` **什么都不做**，绝不打断正在跑的运动 |
| 惯性用"指针速度"算 | 拖完**停住**再松手，球还会弹出去 | 用**球自己的位移**算，时间窗口以**松手那一刻**为准 |
| 数值整块重写 | 颜色/数字全是"瞬变"（节点被换掉，CSS 过渡无从生效） | 数值行**增量更新**，只改了的那部分才碰 DOM |
| 关键帧动了有过渡的属性 | 开关时大小球**瞬间切换**（动画覆盖过渡） | 关键帧**只动 `transform`**；淡入淡出交给 `opacity` 过渡。开关动画现在直接由 **JS（Web Animations API）** 驱动，`animate()` 调用可被测试计数 |
| 关键帧漏了 hover 改的属性 | 鼠标悬浮时**瞬间变亮** | `hover/active` 会改的每个属性都必须在过渡列表里（缺了测试直接报"XX 的 YY 没有过渡"） |
| 数字与单位对不齐 | 数字比旁边的 `ms` 低一点 | 数字动画必须是**单层 inline-block 从下浮入**（基线天然对齐）；"两层 + `overflow:hidden`"会错位、还会按旧宽度**裁掉长文本** |
| 长文本被裁 | "线路"里的长主机名显示不全 | 「线路」**点击复制**完整名称（标题处闪一句"已复制线路"）；其它列被裁时悬浮弹完整内容 |

### 视觉规范

* **不许截断**：11 国语言逐个切，面板里每个标签/数值/副行/按钮/语言名/标题都不许 `scrollWidth > clientWidth`。
* **切语言不许跳版**：标签 `nowrap`（超长才省略）、语言行的标签固定宽 → 语言按钮与菜单**宽度恒定**。
* **`z-index` 不要超过 `2147483647`**（超了会被浏览器忽略，菜单就被面板盖住 —— 踩过）。
* **`font:11px/1.4 inherit` 是非法值**（`inherit` 不能写在 `font` 简写里），整条声明会被丢弃 ——
  踩过：按钮/菜单项一直按 16px 渲染，语言名因此显示不全。用 `font-size` + `line-height` 分开写。
* 开关的视觉语义：**关 = 稍暗但保留颜色**（`saturate(.85) brightness(.9)`）；**开 = 提亮**
  （`brightness(1.18)`，和 hover 同一种"更亮"）+ 黑投影减弱 + 一层很轻的白色光晕呼吸。
  **不要**激活环、**不要** `currentColor` 大片染色（被用户评价过"华而不实"）。
* 阿拉伯语等 RTL：面板保持 LTR 排版，文本节点用 `unicode-bidi:isolate`
  （否则 `62 ms` 会被翻成 `ms 62`、`⚡` 会跑到右边）。

## 6. 多语言与设置缓存

* 11 国语言：`en / zh / ja / ko / ru / ar / fr / es / de / pt / vi`（与 TankTrouble-Chat-Fix 一致）。
* 默认跟随 `navigator.language`；用户选过就以存档为准。
* 按钮里的语言名**实测自适应**：11px 起，放不下就 0.5px 一档往下缩（最多 9px）——
  不同系统字体宽度不同，写死字号总会有人被截断。
* 缓存（`localStorage` 键 `ttn.hud.v4`）：`{ x, y, ball, hidden, lang, smooth }`
  —— 悬浮球位置/收起状态、面板显隐、选中语言、优化开关。老存档缺字段也能读。

## 7. 开发与测试

```bash
node ttn-smoke-test.js      # 304 项逻辑测试（vm 沙盒：可派发真实 pointer 事件）
node ui-check-build.js      # 生成 _ui_check.html
# 用无头浏览器跑（Chrome；Edge 也可以）：
chrome --headless=new --disable-gpu --no-sandbox --disable-extensions \
  --window-size=1280,800 --user-data-dir=_tmp --virtual-time-budget=90000 \
  --dump-dom file:///<绝对路径>/_ui_check.html        # 结果在 <title> 里，190 项
```

测试纪律（这个项目一直在用）：

1. **先复现**：用真实指针/事件序列复现用户报的现象，而不是"我觉得修好了"；
2. **反例验证**：把修复回退，确认对应测试**变红**（否则那条测试是假的）；
3. **量化**：改手感/改指标都给数字（例如"1px/ms 的甩动：222px/784ms → 125px/352ms"）。

### 动画相关：三个"看着像玄学"的坑

1. **`filter` 列表形状必须一致，否则只能离散插值。**
   `saturate(.85) brightness(.9)` → `brightness(1.18)` 这种"少了/换了函数"的写法，
   规范规定按**离散**处理 —— 动画在播，值却是到点就跳（用户看到的"瞬变"就是这个）。
   统一写成 `saturate(...) brightness(...)` 才能插值。
2. **"动画在播"和"值在插值"是两件事。** 数 `Element.animate()` 调用只能证明前者。
   要证明后者：把动画 `pause()` 后把 `currentTime` 钉到 50%，再读 `getComputedStyle` ——
   得到的值必须**既不是起点也不是终点**。（这个判据不依赖时间推进，无头环境也能测。）
3. **关键帧不要动有过渡的属性**（动画会覆盖过渡）；`prefers-reduced-motion` 不要整个跳过动画，
   改成"更短、幅度更小"。

⚠️ 注意：无头环境里 **CSS 过渡不会推进、`transitionrun` 事件也不来、rAF 不跑**，
所以"有没有动画"这类断言要用**可计数的信号**判定 —— 例如数 `Element.animate()` 的调用次数。

## 8. 未做的事 / 待验证

* ❌ 自建服务器 / 加速器 / 改网络配置：明确不做（用户要求"人人可用、不绑网络配置"）。
* ❌ 用服务端时间戳过滤旧状态：协议里没有时间戳，做不到。
* ⚠️ 面板显示的延迟来自**独立小包探测**，它测不出大流量状态流的抖动 —— 抖动要另看"小抖动/卡顿"两行。
* ⚠️ 优化只作用于**画面**；判定永远以游戏/服务端为准（这是刻意的）。
